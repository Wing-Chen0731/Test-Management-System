# 测试管理系统作品使用操作流程

## 1. 作品展示什么

- 页面：测试用例 CRUD、搜索、筛选、分页、接口冒烟
- VS Code 终端：单元、接口、UI、集成和数据驱动测试
- 浏览器：业务页面、Swagger、JaCoCo、Allure
- Docker：Testcontainers 自动启动 MySQL + Redis
- GitHub：Actions 自动测试、覆盖率门禁和报告产物

页面中的 `复制` 按钮只复制命令，测试仍由 Maven 在终端执行。

## 2. 获取项目

需要使用 Git 和 GitHub Actions时，推荐先 Fork，再克隆自己的仓库：

```powershell
git clone 你的仓库地址
cd Test-Management-System
```

直接下载 ZIP 也能运行项目和测试，但没有 Git 历史，且不能直接执行
`git push`。ZIP 用户需要自行 `git init` 并绑定自己的远程仓库。

## 3. 环境和首次初始化

必须安装：

- JDK 17
- Maven 3.9+
- 浏览器

多容器测试还需要 Docker Desktop。首次执行 UI 测试前，在项目根目录安装
Playwright Chromium：

```powershell
mvn -q test-compile org.codehaus.mojo:exec-maven-plugin:3.5.0:java "-Dexec.mainClass=com.microsoft.playwright.CLI" "-Dexec.classpathScope=test" "-Dexec.args=install chromium"
```

## 4. 启动演示页面

开发模式使用 H2，不需要 MySQL：

```powershell
mvn spring-boot:run
```

访问：

- 首页：<http://localhost:8080/>
- Swagger：<http://localhost:8080/swagger-ui/index.html>
- H2 Console：<http://localhost:8080/h2-console>

H2 Console 使用 JDBC URL `jdbc:h2:mem:testdb`，用户名和密码均为 `sa`。

JAR 不会随 GitHub 源码下载，需要先构建：

```powershell
mvn -q clean package
java -jar target/test-management-1.0-SNAPSHOT.jar
```

## 5. 页面操作

1. 点击 `初始化演示数据`
2. 演示新增、搜索、筛选、编辑和删除
3. 点击右侧 `接口冒烟` 的 `运行`
4. 打开 Swagger、OpenAPI 和报告入口

初始化数据已做去重；接口冒烟会自动创建、查询、更新、校验并删除临时数据。

## 6. 自动化测试

所有命令都在项目根目录执行。

### 单元测试

```powershell
mvn -q "-Dtest=TestCaseServiceTest,ResultTest" test
```

### 接口和数据驱动测试

```powershell
mvn -q "-Dtest=TestCaseControllerTest,TestCaseDataDrivenTest" test
```

### Playwright UI 测试

测试会自行启动随机端口的 Spring Boot，不需要先启动 `8080`：

```powershell
mvn -q "-Dtest=SwaggerUITest" test
```

YAML 驱动 UI 测试：

```powershell
mvn -q test-compile "-Dit.test=SwaggerYamlDataDrivenIT" failsafe:integration-test failsafe:verify
```

无界面执行示例：

```powershell
mvn -q "-Dtest=SwaggerUITest" "-Dplaywright.headless=true" test
```

### MySQL + Redis 多容器测试

先启动 Docker Desktop，再执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\run-tests.ps1
```

测试由 Testcontainers 创建 MySQL 8 和 Redis 7，结束后自动销毁，不依赖
`docker-compose.yml`。

### 全量验证和覆盖率门禁

```powershell
mvn -q clean verify
```

该命令执行单元、接口、数据驱动、UI 和集成测试，并生成 JaCoCo 报告。
Docker 可用时会执行多容器测试；Docker 不可用时该项按配置跳过。

## 7. 报告

JaCoCo 在 `verify` 阶段自动生成：

```text
target/site/jacoco/index.html
```

Allure 先使用已有测试结果生成 HTML：

```powershell
mvn -q allure:report
```

```text
target/site/allure-maven-plugin/index.html
```

系统运行时也可访问：

- <http://localhost:8080/reports/jacoco/index.html>
- <http://localhost:8080/reports/allure/index.html>

## 8. MySQL 模式

`docker-compose.yml` 用于启动持久化 MySQL，不用于 Testcontainers：

```powershell
docker compose up -d
$env:SPRING_PROFILES_ACTIVE="prod"
mvn spring-boot:run
```

默认连接信息为数据库 `test_management`、用户 `test`、密码 `test`。
可通过 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 覆盖。

## 9. GitHub Actions

工作流会执行：

1. 安装 JDK 17 和 Playwright Chromium
2. 运行 `mvn -B clean verify`
3. 在 Ubuntu Docker 环境执行 Testcontainers
4. 检查 JaCoCo 80% 门禁
5. 生成并上传测试结果、JaCoCo、Allure 和 UI 截图

推送自己的 Fork：

```powershell
git status
git add .
git commit -m "demo: complete test management project"
git push -u origin HEAD
```

## 10. 面试演示顺序

1. 首页初始化数据并演示 CRUD
2. 运行页面内接口冒烟
3. 终端运行接口数据驱动测试
4. 运行 Playwright UI 测试
5. 打开 JaCoCo 或 Allure 报告
6. Docker 已启动时运行多容器测试
7. 展示 GitHub Actions 最近一次成功记录

现场优先演示 1 到 2 条测试命令，不建议临时执行完整流水线。

## 11. 常见问题

- `ERR_CONNECTION_REFUSED`：先执行 `mvn spring-boot:run`
- Playwright 提示浏览器不存在：重新执行第 3 节 Chromium 安装命令
- 多容器测试失败：确认 Docker Desktop 已启动且 `docker info` 成功
- JaCoCo 不存在：执行 `mvn -q clean verify`
- Allure 不存在：先运行测试，再执行 `mvn -q allure:report`
- Maven 提示没有 POM：先进入包含 `pom.xml` 的项目根目录
- `clean` 无法删除 JAR：先停止正在运行的 `java -jar` 或 `spring-boot:run`
- PowerShell 参数解析错误：保留命令中的双引号，不要拆开 `-Dtest` 参数
